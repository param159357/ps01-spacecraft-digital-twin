## How to get it running

```bash
docker compose up -d db
cd backend && ./.venv/Scripts/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
cd frontend && npm run dev
```

Sign in as `simulator` at <http://localhost:3000> and press **Start**. Account passwords
were generated by `scripts/seed_users.py` and are not in the repo; re-run it with
`--reset-passwords` if they are lost.

Tests: `cd backend && ./.venv/Scripts/python.exe -m pytest -q` (needs the `db`
container; they use a separate `ps01_test` database).

Keep the PostgreSQL container running. `docker compose down` is safe; **never
`docker compose down -v`** — that deletes the `ps01_pgdata` volume and every stored run.

## What Phase 6 must add

Section 15 lists five tasks. Mapped onto this repository:

1. **Timeline events.** Write an `incident_events` row on every lifecycle change,
   severity change, acknowledgement and linked command outcome, from
   `backend/app/operations.py`. Add bounded historical queries (explicit time window,
   explicit run/source, capped row counts) in `backend/app/analysis/`.
2. **Synthetic month.** `scripts/generate_history.py` — deterministic, seeded, cached by
   seed plus config version, stored as `runs` rows with `source='SYNTHETIC'`. One
   configurable recurring equipment issue plus clean comparison periods. Minute
   summaries in `history_buckets`; short 1 Hz excerpts in `telemetry_frames` around
   selected incidents only. Measure and record generation time.
3. **Statistics.** Distinct incident counts, durations, severity mix, coverage, and
   commanded-versus-measured comparison (command missing / rejected / accepted but
   ineffective / outcome unknown because data is absent), for daily, weekly and monthly
   windows.
4. **UI.** Period and source selection plus the historical evidence views on
   `/history/`.
5. **Deterministic report template and the read-only investigator tool functions**
   (`get_incident_evidence`, `get_recent_telemetry`, `find_similar_incidents`,
   `get_forecast_comparison` — section 10.2). Phase 6 builds the *functions* and the
   template. **No LLM, no provider, no queue — that is Phase 7.**

## Traps that will cost you time

1. **Uvicorn runs without `--reload`, deliberately** — one process owns the simulation
   loop, and autoreload would fork a second one. **Restart it after every backend
   change** or you will debug stale code. Check ports 3000/8000 for leftovers first.
2. **`alembic check` must stay clean.** If you add a column or table, hand-write the
   migration to match the model exactly. Note that `unique=True, index=True` produces a
   *unique index*, not a constraint plus a plain index — that exact drift has already
   cost this project once.
3. **Tests repoint `DATABASE_URL` to `ps01_test` in `conftest.py` before any engine is
   built.** A new test module must not import the engine at module scope.
4. **Use `127.0.0.1`, never `localhost`, in database URLs.** `localhost` resolves to
   `::1` first and Postgres publishes on IPv4 only; that took the suite from 8 s to
   130 s once.
5. **PowerShell 5.1 has no `&&`.** Use `;` or separate commands.
6. **Do not integrate the thermal model with a one-minute step.** `thermal_substeps` in
   `simulation/models.py` exists precisely for this; section 10.5 calls the naive version
   out by name.
7. **Do not run a 30-minute forecast at every historical second**, and do not store 2.6
   million raw frames. Minute buckets plus short excerpts.
8. **A model-level test is not an observation-path test.** A Phase 2 typing defect in
   `TelemetryFrame.engineering` survived three phases because every test exercised the
   model and none ever built a frame; it froze every console the first time a real load
   was shed. Whatever you add, exercise it through the actual HTTP response, not only
   through the function.
9. **Hidden truth stays hidden.** History queries, statistics and the investigator tool
   functions read stored observations only — `telemetry_frames`, `incidents`,
   `incident_events`, `commands`, `forecasts`. They must never read
   `runs.private_checkpoint` and must never import from `app.simulation.truth`.
   `SimulatorTruth.hidden_fields` currently holds seven keys, but the guard constant
   `HIDDEN_FIELDS` in `backend/tests/test_simulation_api.py` still lists only four —
   extend it to include `computer_resets`, `branch_stuck_on` and `isolator_failed`, and
   apply the same raw-text grep to every new history and tool response.
10. **One long incident is counted once.** Count `incidents` rows by id — never
    `incident_events` rows, never telemetry frames. A recurrence after resolution is a
    *new* incident row linked to the previous one, and that distinction is the whole
    point of D05.
11. **Synthetic and live are never silently mixed.** `runs.source` carries a CHECK
    constraint of `LIVE | SYNTHETIC | REPLAY`. Every summary response must state its
    dataset, its date window and its coverage.
12. **Daily means a completed UTC day.** Weekly is a selected seven-day window, monthly a
    selected completed calendar month. Partial or custom windows must be labelled as
    such with their coverage.
13. **Derive recurrence counts from stored events.** Section 10.5 forbids hard-coding the
    answer the demo is supposed to discover.
