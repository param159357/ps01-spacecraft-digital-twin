```bash
docker compose up -d db
cd backend && ./.venv/Scripts/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
cd frontend && npm run dev
```

1 Hz to every console. Account passwords were generated by `scripts/seed_users.py` and
are not stored in the repo; re-run it with `--reset-passwords` if they are lost.

Tests: `cd backend && ./.venv/Scripts/python.exe -m pytest -q` (needs the `db` container;
they use a separate `ps01_test` database).

## Traps that will cost you time

These are all real problems that were already hit and fixed. Re-introducing them is easy.

1. **Never let hidden simulator truth reach an operational response.** The split lives in
   `backend/app/simulation/truth.py`: `generation_factor`, `extra_load_w`,
   `heater_stuck_on` and `contact_loss` are hidden; `payload_duty_percent` and the
   commanded heater mode are published as `known_commands` on purpose, because that is
   what makes an actuator mismatch detectable. `test_operational_responses_never_carry_hidden_truth`
   greps raw response text for the hidden names — keep it passing.

2. **Rules and forecasts must read observations only.** Use `TelemetryFrame.value_if_valid()`,
   not `values[...]`. A channel whose quality is not `VALID` has no usable value. Never
   read `runs.private_checkpoint`, and never import from `simulation.truth` into
   `monitoring/` or `forecasts/`.

3. **Starlette's `TestClient` cannot stream SSE.** It hangs forever. The stream is
   verified against a real Uvicorn server with `curl -N`; unit tests cover the bus and
   role filtering only. Do not "fix" this by adding a TestClient SSE test.

4. **`str(SQLAlchemy URL)` masks the password as `***`.** Pass `URL` objects around, or
   use `render_as_string(hide_password=False)`.

5. **Persist before publishing.** `runner._tick` writes the frame, then publishes. A
   storage failure pauses the run and surfaces an explicit error; it is never shown as
   recorded data. Keep that order.

6. **Do not hold `runner._lock` across a network call.** It guards run changes and
   command application. Storage writes happen off it, and a frame from a superseded run
   is discarded rather than attached to the new one.

7. **Sensor noise is clamped to the encodable range** in `observation.py`, so `INVALID`
   keeps its meaning for genuinely impossible model values. Do not remove the clamp; it
   was added because a healthy heater at 0 W kept reading INVALID.

8. **`npm run build` uses its own `distDir`** (`.next-export`) so it does not corrupt a
   running `npm run dev`. Leave that alone.

9. **Config is versioned.** Changing `spacecraft.yaml`, `rules.yaml` or `actions.yaml`
   means bumping `config_version` and recording the change in `docs/decisions.md`.

## What Phase 3 has to build

Target: the first complete loop — fault, alert, forecast, action, approval, observed
recovery — runnable through the real UI. Section 15 lists the tasks; section 9 has the
contracts, which already exist as types in `backend/app/contracts/actions.py` and
`incidents.py`. Implement against those types rather than inventing new shapes.

Suggested order, because each step is testable on its own:

1. **Rules** in `backend/app/monitoring/` — `DATA_STALE`, `GENERATION_SHORTFALL`,
   `ENERGY_RESERVE`, `THERMAL_LIMIT`, `SUPPLY_SHORTAGE` first. Flip `implemented: true`
   in `rules.yaml` only as each one actually works; `/api/config/coverage` reads that
   flag and the UI displays it, so a premature flip makes the app lie.
2. **Incident engine** — dedup by run + rule family + affected entity while active,
   `PENDING → OPEN → RECOVERING → RESOLVED`, acknowledgement orthogonal to lifecycle,
   hysteresis, and a healthy dwell that missing data can never satisfy.
3. **Forecast** in `backend/app/forecasts/` — 30 simulated minutes, recomputed every 5 s
   and immediately on a new incident or command. Reuse `simulation/models.py`; it is pure
   and already shared for exactly this. Split integration at illumination boundaries using
   `environment.schedule_boundaries()`. Run it off the event loop from an immutable
   `truth.copy()`, keep at most one running plus one pending, and check the run and
   revision still match before publishing.
4. **`REDUCE_PAYLOAD_POWER`** — baseline versus action from the *same* observed start.
   Set `enabled: true` in `actions.yaml` only once it is implemented and tested.
5. **Proposal and command** — 30 s TTL, master-only, CSRF, idempotency key. The
   `uq_commands_idempotency` constraint already makes double execution impossible; return
   `ACCEPTED` then separately `APPLIED`, and track observed outcome afterwards. A command
   that applied but did not help must report that honestly.
6. **Master UI panels**, then run D01 and D02 through the actual controls.

Acceptance is in section 15 under Phase 3. AI is explicitly **not** needed for any of it.
