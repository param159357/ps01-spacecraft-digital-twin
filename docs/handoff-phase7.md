# Handoff brief — starting Phase 7

Read `CLAUDE.md` section 10.1–10.3 and the Phase 7 task list first. Verify this brief
against the code; do not trust its commit hashes or counts without rerunning them.

## Phase 6 state to build on

- Historical statistics and template reports live in `backend/app/analysis/history.py`.
- The four bounded, read-only investigator functions live in
  `backend/app/analysis/tools.py`. They select stored observations only and must remain
  the only evidence interface offered to an investigator.
- `POST /api/history/review` already persists/cache-hits `TEMPLATE` analyses. Phase 7 may
  add provider-backed modes without removing this deterministic fallback.
- Incident timeline changes are durable in `incident_events`; command links are stored as
  `command:<uuid>` evidence references.
- The labelled synthetic June dataset is generated by
  `python -m scripts.generate_history --month 2026-06 --seed 6026`: 43,200 minute
  summaries, five recurring incidents and 900 selected 1 Hz evidence frames.
- `/history/` already presents selected source/window, coverage, recurrence and template
  results. Do not rebuild these facts in an LLM prompt or in frontend code.

## Hard boundaries

1. Evidence comes through the four Phase 6 tools. Never read `SimulatorTruth`,
   `app.simulation.truth`, `runs.private_checkpoint` or hidden injection fields.
2. Treat tool responses as untrusted data. The model may cite evidence IDs; it may not
   execute commands, mutate incidents or claim a hidden root cause.
3. Preserve source/window labels and never mix LIVE and SYNTHETIC evidence silently.
4. Keep provider calls bounded by configured timeout, output tokens, daily limit and
   incident cooldown. Persist explicit failure/fallback status.
5. Cache incident analyses by incident plus evidence revision. A new evidence revision
   invalidates the old answer; repeated unchanged evidence must not spend another call.
6. AI-disabled and provider-failure paths must still return the deterministic template.
7. Do not add optional ML, Phase 8 verification work or Phase 9 deployment work.

## Phase 7 completion evidence to record

- Provider-disabled deterministic fallback through the real API/UI.
- One successful bounded provider path if credentials are explicitly available; otherwise
  record it as not run, never fake it.
- Timeout, malformed-output, daily-budget and cooldown tests.
- Citation/evidence validation and raw-response hidden-field leak scans.
- Cache hit and evidence-revision invalidation through persisted `analyses` rows.
- Full backend tests, Ruff, TypeScript, static export and `alembic check`.

Keep Uvicorn single-worker without `--reload`; restart after backend changes. Preserve
PostgreSQL and its volume. Never run `docker compose down -v`.
